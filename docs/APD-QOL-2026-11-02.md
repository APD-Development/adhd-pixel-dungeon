## Dew pickup

Grass still makes its original independent seed/dew rolls. If the hero tramples grass and it produces dew beneath the hero, record a one-shot request for the actual loose dew item. The item remains on the floor through the movement action. At the next hero turn, after FOV refresh, collect through the ordinary `Dewdrop.doPickUp` path and pay its normal one-turn pickup delay. At normal speed this is one movement turn plus one pickup turn, not free collection during movement.

Options -> UI -> Dew pickup settings opens a compact native dialog. `apd_auto_grass_dew` defaults true; `apd_auto_dew_with_enemies` defaults false. Both persist independently. The latter is disabled in the dialog while automatic collection is off, retaining its stored preference. Visible living enemies block collection unless explicitly allowed; recheck after movement so newly revealed enemies count. Allies and unseen enemies do not block it.

No full/missing/lost Waterskin auto-consumption or healing. Full or missing Waterskins leave ordinary retrievable dew. No remote collection of enemy-trampled grass, pre-existing floor drops or other loot. Preserve mixed-pile order/items, normal dew merging, quantities, capacity and feedback. The exact level/cell/heap/item/action are revalidated once; missing or changed targets, manual replacement actions, paralysis, death and stale requests do not repeat. A continuing travel action resumes after the separate pickup action. Requests are transient; ordinary saved dew remains retrievable after restart.

## Manual search memory

Only deliberate Search records currently visible wall/decorated-wall/secret-door-looking-wall/bookshelf cells inside the existing search loop. Automatic searching does not mark. Search radius, Foresight, secret discovery rolls, turn/hunger costs and terrain are unchanged.

A small original pixel check is a separate batched tile layer beneath normal fog and wall blockers. It does not handle touches. Known marks persist through revisits/recreation. Examine adds a plain “manually searched” sentence. The marker records an action, not a new secret detector; discovered doors/open floors no longer display it.

Each Level owns a `SearchedWalls` bitset. Optional sparse `apd_searched_walls_v1` indices are written only when nonempty, retaining original untouched-floor payloads/goldens. Old saves start unmarked; duplicate/out-of-range cosmetic indices cannot block loading. Resetting/replacing a floor clears its own memory; floor data is independent. Original PNG source: `tools/build_searched_wall_marker.py` (GPL3-or-later, original geometry, no external artwork).

## Affected-item ring descriptions

New readouts appear in affected-item descriptions only, including when a custom item note exists. Ring descriptions are unchanged. Both equipped, identified rings combine; hide the new block if any worn ring has unknown identity/level/curse, or the affected weapon/armor upgrade level is unknown. Magic immunity suppresses inactive contributions. Preview does not equip items, roll damage, consume buffs, modify a Spirit Form stored item, or advance time.

| Ring | Affected-item display |
|---|---|
| Sharpshooting | Missile/bow base damage without and with the actual bonus; missile durability contribution. Bow and each missile use their own existing scaling/augment. |
| Accuracy | Weapon accuracy multiplier, explicitly not hit probability. |
| Furor | Weapon attack-speed multiplier. |
| Force | Base armed melee damage range; an active Brawler stance is labelled as unarmed replacement, not extra armed damage. No missile bonus is invented. |
| Might | Strength available to the weapon/armor without and with Might. Equipment's requirement stays unchanged. |
| Evasion | Wearer evasion contribution on armor, before armor adjustments. |
| Haste | Wearer movement contribution on armor, before encumbrance. |
| Elements | Supported elemental damage/effect-duration contribution on armor; no claim to resist all damage. |
| Tenacity | Incoming-damage contribution on armor at current HP; recomputes with HP. |
| Energy | Wands, imbued Mage staff, class-armor charge, and the twelve artifact classes whose actual charge code uses Energy. No bonus is claimed for Chalice of Blood or Cape of Thorns. |
| Arcana | Existing detailed, conditional weapon-enchantment/armor-glyph readouts are retained; their regressions remain required. |
| Wealth | Does not change already-carried item stats. No false item damage/value/quantity bonus is displayed; existing ring description retains its generation/drop explanation. |

The new block labels ring contributions before other buffs, talents, equipment, targets and dungeon rules. It is not a guaranteed damage-on-hit or hit-chance forecast. Shared pure overloads retain the original gameplay arithmetic for numeric multipliers. Spirit Bow and hero strength expose the same existing calculation with an explicit ring input for read-only counterfactuals. Actual ring values, combat/scoring mechanics and RNG are unchanged.
