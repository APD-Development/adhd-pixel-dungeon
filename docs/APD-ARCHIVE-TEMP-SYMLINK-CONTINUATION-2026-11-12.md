**Source defect:** ImportArchive.importZip clears preexisting `import-tmp` through `deleteTree`, which recursively invokes Java File.listFiles. If that staging path or one of its children is a symlink to an external directory, the old implementation can recurse into, and remove, external files. This is a source-evidenced safety risk, not an owner-phone incident claim.

**Isolated fix:** prevent recursive cleanup from following any noncanonical child. A link itself is unlinked, without traversing its target. Before staging, explicitly verify that the `import-tmp` canonical destination is the direct child of the canonical root. New real-filesystem tests cover top-level and nested staging symlinks while preserving external marker bytes and successfully importing legitimate logs. Existing historical first-wins manifest handling and previously accepted destination symlink guards are mandatory regression controls.
