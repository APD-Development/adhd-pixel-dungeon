# APD-0001: Starvation damage consumes shielding before HP

## Original problem
In Shattered Pixel Dungeon, `ShieldBuff.processDamage` returned early for any damage whose
source was `Hunger`, so starvation damage went straight to HP and ignored active shielding.
A hero at 1 HP with a full shield would still die from a starvation tick. Shielding is meant to
protect HP, so this felt like shielding not working.

## Change
- `ShieldBuff.processDamage` no longer exempts `Hunger` damage. Starvation damage is absorbed by
  shielding (highest `shieldUsePriority` first, as for any other damage) and only the leftover
  reaches HP.
- `Hunger.java` is unchanged: it already sends starvation damage through `Char.damage`, which calls
  `ShieldBuff.processDamage`. Nothing in it reads shielding, so shielding does **not** reduce hunger
  level or cure starving; it only absorbs the damage.

## Reasoning
Removing the exemption is the smallest fix and keeps one damage path for everything. No save data
or new fields are involved.

## Not changed (deliberately)
`Char.damage` still skips the Warrior's broken seal shield activation for `Hunger` damage, so
starving does not trigger the seal's "below half HP" shield.

## Regression test
`ShieldHungerTest`: 1 HP, starving damage source, active shield, starvation tick -> shield drops,
HP stays 1. It exercises `ShieldBuff.processDamage` with a `Hunger` source on a lightweight `Char`;
a full `Hunger.act()` run needs the whole game world and was not practical in a unit test.
