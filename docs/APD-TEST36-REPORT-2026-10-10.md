## Actual fixes since TEST31

Reading position lost after app switching: WndUimsdText and WndUimsdTopic had semantic restorers, but reconstruction returned each ScrollPane to the top. The restorer now snapshots x/y before destruction, recreates the same content and clamps the position using the existing pane API. Preview and guide windows retain their own positions; taller/narrower layouts cannot leave an invalid offset. This does not preserve UI across Android process death. Commit a0ab5303089232afdce61ecec17cf88dca5617a0.

Text filters changed with device language: CONTAINS used default-locale lowercase. Under Turkish/Azeri, uppercase ASCII I no longer matched an ordinary saved “ring” filter. QueryEngine now uses Locale.ROOT on both compared values. Stored queries and recorded text remain untouched. Three permanent tests cover English/ROOT/Turkish/Azeri matching, persisted combined filter/sort/columns with equal values and literal query data. Commit c3c1e48f0325d68baa6b8822088364cdab68f170.

Six additional warning/status paths disappeared on scene recreation: invalid numeric filter input in two paths, two grouped-column notices, empty-history questions and report/export callback results still used anonymous or non-restorable WndMessage windows. They now reuse WndUimsdText with the same raw message, wrapped scrolling display and semantic restoration. Restoration redisplays the result without reexecuting export, query edits or other operations. Commit bff080101d532dc8c96c8a8111b89bc7a06c2823.

Saved grouped sorting changed with device language: Aggregate.id also used default-locale lowercase. MIN/COUNT_DISTINCT identifiers changed under Turkish/Azeri, so stored grouped-sort IDs no longer identified the right result column. Two additional red tests reproduce changed aggregate IDs and a wrongly ordered saved minimum-group view. Locale.ROOT stabilizes the existing IDs and hash keys; no migration or history rewrite. The seventh remaining warning path, the locked-tour notice, also uses the restorable UIMSD text window without altering its ten-genuine-run condition. Commit 3b4348159094436d27476d1932bd905c90e43718.

Tour choice windows vanished after scene recreation: the first-tour offer and own-run/sample-data chooser used anonymous WndOptions constructors that PixelScene could not reconstruct. They now use existing responsive WndUimsdChoices and pure display factories. Restoring never starts/restarts a tour or generates sample history; callbacks target the current scene. Later/Back dismiss normally and a subsequent reset does not reopen the dismissed choice. Existing guide-seen preference and unlock/demo rules are unchanged. Commit 7d33f22fc96567f1451e7cda4d8c5a17902a523b.

Weapon accuracy displayed the wrong known curse penalty: the active Wayward buff divided actual combat accuracy by five, but the weapon description ignored it. A known active curse therefore displayed 100% when combat used 20%. The display now reads that existing modifier only when the curse is identified and active; no curse properties are revealed for unidentified items, no other weapons inherit the penalty, and no combat calculation changes. Commit 22b4285f0e32d7853d8d293e5d2fea65289cdfa0.

Historical saved-view sorting remained wrong: earlier Turkish/Azeri builds had already stored dotless-I aggregate sort identifiers, so stabilizing new IDs alone did not restore those older sorts. QueryCodec now resolves only historical MIN/MEDIAN/COUNT_DISTINCT aliases that correspond exactly to the query's actual aggregates. Unknown/future sorts and literal group keys remain untouched. Saved files are not rewritten on read, and the resolved in-memory IDs preserve normal header/selection matching. Commit e9b9e1971fed601291d19d336c202c2447395938.
