# Automatic inventory ordering — 2026-11-08

Approved owner rules: weapons/armor by ascending tier, then ascending known upgrade; rings and other upgradeable categories by known displayed upgrade; consumable bags by ascending stack count; holster throwables by tier/upgrade before wands by upgrade. Unidentified items last within each category; no hidden upgrade/curse/type tie-breaker. No manual sort button or preference.

Root cause: the previous Item comparator only compared Generator.Category.order; all melee tiers share the same superclass and category ordering did not distinguish actual tier or upgrades. Windows copied/iterated stored insertion order, so existing inventories and later upgrades had no fresh display ordering. Consumable quantities were never a sort key.

InventoryOrder supplies shared, knowledge-safe comparison. Bag.itemsForDisplay returns a stable sorted snapshot of the same item objects. WndBag and InventoryPane use it; WndQuickBag retains equipped priority and uses the matching bag rules. Collection's existing Item comparator now shares tier/knowledge ordering. Original equipped rows, second weapon priority, item identities, stack quantities, quickslot references, RNG and serialization format remain. Unknown items retain stable order except visible stack counts in consumable bags; unknown levels are never read for sorting. Identification triggers the existing display refresh path.

Eleven added regressions cover tier-over-upgrade priority, armor strength not used as tier, rings/wands/artifacts/trinkets, consumable quantities across item types, holster throwables/wands, hidden-level independence and identification, unidentified consumables, live quantity/upgrade changes, existing save/load, equipment/quickslot identities and RNG/item-knowledge purity.
